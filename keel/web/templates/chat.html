Keel

What it is. A retrieval and agent appliance that runs where the documents live: one machine on premise, or an organisation's own Azure tenancy. This instance is the on-premise build with a small CPU model.

What it is for. A team asks questions of its own documents and gets answers citing the exact passage behind each claim. The entitlement filter sits inside retrieval, so each person reads what their role allows and the model receives only entitled passages.

How it is built. A keyword search and a vector search, combined by reciprocal rank fusion and reranked, with the entitlement filter applied inside each query. A local model writes the answer, and every request appends to a hash-chained ledger that verifies from an exported file.

How it runs internal operations. Agent mode calls five typed tools under a written policy: document search, a calculator, read-only SQL, an allowlisted HTTP GET that refuses outright under air-gap, and ticket creation. Write actions wait in an approval queue for a person, and each step is recorded.

Hosted demonstration running five fixture documents of invented content. The access-control comparison sits on the overview page, where one restricted question is asked as two users side by side. About this demonstration

Setting this up for your own work
Add your documents
{% if ingest_enabled %} Upload one from the Documents section, choosing the access tags that decide who can retrieve it. {% else %} Run keel ingest ./handbook.pdf --tags public, or point it at a manifest for anything larger than a handful of files. {% endif %} PDF, DOCX, Markdown, HTML and plain text all load.
Connect a model
keel setup looks for one already running on this machine and reads its model list back. Ollama, LM Studio, llama.cpp and vLLM all work, as does any hosted OpenAI-compatible endpoint. keel doctor names the fix when something is unready.
Run it in your own Azure
keel setup --profile azure takes the endpoints from your own subscription, reached through a user-assigned managed identity that keeps keys out of the code and out of the configuration. deploy/azure/deploy.ps1 creates those resources for you and prints them.
Decide who reads what
Tags are the whole access-control model. A reader holding any one of a document's tags can retrieve it, and the filter runs inside retrieval, so a document outside someone's tags never reaches the model that answers them.

The setup guide covers each of these in full.

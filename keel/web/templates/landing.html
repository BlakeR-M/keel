Sovereign retrieval and agent appliance

Ask your own documents. Keep them in the building.

Keel runs where the documents already live: one machine on premise, a network with no route out, or your own Azure tenancy on managed identity with no keys in code. Permission filtering happens inside retrieval, so the model only ever sees chunks the person asking is entitled to. Every answer cites the exact chunk it came from, every write action waits for a person, and every request lands in a hash-chained ledger.

What that shows

The filter sits inside the retriever
BM25 and the vector index each apply the entitlement filter as part of their own query, before the two result sets are fused and before the reranker sees anything. An unentitled chunk is never a candidate, so it cannot be reranked into a prompt by a high similarity score.
The refusal costs zero model calls
When nothing entitled clears the relevance line, Keel says so and stops. No prompt is built and no text is generated, so there is no output for a clever question to steer.
The boundary is checked twice
Finding A7 of the review added a second entitlement check at the generation boundary, so a retrieval bug alone is not enough to put a restricted chunk in front of the model.
The answer carries its source
Each citation opens the exact chunk it came from, and the source viewer applies the same entitlement check, so a citation link is never a way around the filter.

Code: keel/retrieval/bm25.py, keel/providers/local_index.py, keel/answer/engine.py. Proof: tests/redteam_acl_and_retrieval_leakage.py.

Air-gap mode installs guards across the whole process. Type a host and Keel starts a child process with the guard on, points every guarded layer at it, and reports what each one did. The refusal text below comes from the exception itself.

Why each layer is guarded on its own

Name resolution, before the socket
A lookup of <secret>.attacker.example carries the secret to a name server whether or not the connection ever happens, so it is an exfiltration channel by itself. Review finding G1 closed that: names outside the allow list are refused at getaddrinfo, and the control test now asserts that the resolver was never even asked.
The event loop needs its own guard
On Windows the proactor loop connects through ConnectEx and never calls socket.connect, so patching the socket alone leaves a path open. Both loop families are guarded at sock_connect.
Library layers refuse before they send
urllib is checked at OpenerDirector.open, ahead of any handler. httpx is checked by a guarded transport and a request hook, which is what covers the client handed to the OpenAI SDK.
Nothing here can reach out on your behalf
A host outside the allow list is unreachable, which is the property being shown. A host inside the allow list is answered from the policy and never connected to, so loopback stays out of reach as well.

Code: keel/airgap.py. Proof: tests/test_airgap.py and the air-gap section of the ledger and air-gap red-team file.

{# ------------------------------------------------------------------ how it works #}

How a question travels

Every stage below runs on the appliance. Nothing in the path reaches an external service, and the Azure profile swaps the components for their tenancy equivalents without changing the shape.

  1. 1

    Ingest, tagged and screened

    PDF, DOCX, Markdown, HTML and plain text load into section-aware chunks, each carrying the entitlement tags of its document. Every chunk is screened for prompt injection together with its own heading and its document title, because an instruction in a heading rides into every prompt through the source label. A flagged chunk lands in quarantine and stays out of retrieval until a person releases it. Re-ingesting the same bytes adds nothing.

  2. 2

    Retrieve, filtered inside the query

    BM25 and a vector index run in parallel, each applying the entitlement filter as part of its own query. The two result sets are fused, then a cross-encoder reranks what survived. The filter runs before the fusion and before the reranker, so an unentitled chunk is never a candidate for either.

  3. 3

    Answer, or say the sources do not cover it

    A local model writes the answer from the entitled chunks alone, and each claim carries a citation to the chunk it came from. When nothing entitled clears the relevance line, Keel says that plainly and makes no model call at all.

  4. 4

    Act, under a written policy, behind a person

    Agent mode calls typed tools: document search, read-only SQL, a bounded calculator, ticket creation. The policy is written down rather than implied, read-only SQL runs under an authorizer with a size cap, and every write action waits in an approval queue. The policy is re-checked at the moment of execution, so an approval cannot outlive the policy that permitted it.

  5. 5

    Record, in a chain that shows tampering

    Every request, retrieval, answer, tool call and approval appends to a hash-chained ledger. Each row hashes a canonical JSON array of the chained fields, so moving a character across a field boundary changes the hash. The ledger exports as strict JSON lines and verifies from a file, which is what an assessor asks for.

The whole path in detail: the architecture document. The attacks it was designed against: the threat model.

{# ------------------------------------------------------------------ the review #}

The security review, published with its open findings

Before Keel was first published, three independent reviewers were pointed at the security-bearing paths with one instruction: break them. The result is 105 attack tests, 27 findings, and every finding of medium severity or above fixed in the same release. The tests live in the repository and run in the default suite.

  • 27findings
  • 25fixed, each with the test that proves it
  • 2open by choice, one medium and one low
  • 174adversarial cases in the suite

The two that stay open, and why

Both are recorded as strict expected failures, so the day either one starts passing the suite says so. The medium is a paraphrased injection carrying no trigger word the heuristics key on, which the language-model judge at ingest covers instead. The low is a heuristic false positive on a genuine operations note, which an operator releases from the quarantine list. Publishing them is the point: a control list with nothing open on it is a control list that has not been tested.

{# ------------------------------------------------------------------ deployment #}

Where it runs

On premise, one machine

A Python process, a SQLite store and a local model server. Compose files and native runners ship in the repository, with a GPU variant for a larger model. Nothing leaves the machine.

On-premise guide

Air-gapped

The same build with KEEL_AIRGAP=1. Egress is refused at five layers, model caches are read from disk with offline flags set, and the allow list holds only the hosts you name. Demonstration two above runs exactly this guard.

Offline operation

Your own Azure tenancy

Azure OpenAI and Azure AI Search reached through a user-assigned managed identity, with no keys anywhere in code or configuration. The Bicep template disables local key authentication on both resources, and continuous integration builds and lints it on every change.

Using it in practice

A fresh clone runs the whole appliance against the fixture corpus with no model server and no network. The full walkthrough, including loading your own documents and reading the ledger, is in the tutorial. 

git clone {{ github }}.git
cd keel
python -m venv .venv && .venv/bin/pip install -e ".[dev]"

keel ingest --manifest fixtures/corpus.yaml          # 5 documents, 27 chunks, 1 quarantined
keel ask 'What is the confidential review code for the 2026 pay round?' --tags public
keel ask 'What is the confidential review code for the 2026 pay round?' --tags public,hr
keel agent "Create a support ticket titled 'Printer down'."
keel approvals list --status pending
keel approvals approve 1 --by owner
keel verify-ledger
keel serve                                           # the appliance, on 127.0.0.1:8400

Every command and flag: the CLI reference. The web app, its routes and its identity model: the web documentation.
